## 2. 关键文件说明 (Key Files)

### 2.1 项目配置文件
| 文件 | 用途 | 优先级 |
|------|------|--------|
| `pyproject.toml` | Poetry 项目配置、依赖管理、构建设置 | **主要** |
| `requirements.txt` | Pip 直接安装时的依赖清单 | 兼容备用 |
| `.env.example` | 环境变量模板（禁止提交敏感信息） | 参考 |

### 2.2 核心入口文件
| 文件 | 职责 |
|------|------|
| `danmaku_listener/__init__.py` | 导出 `DanmakuListener` 类，提供简洁的 API |
| `danmaku_listener/listener.py` | 主类实现，协调各引擎和总线 |

### 2.3 模块组织原则
- **单一职责**：每个模块只负责一类功能（如 `engines/` 只管监听，`adapters/` 只管解析）
- **低耦合**：通过抽象基类（`BaseEngine`, `BaseAdapter`）解耦具体实现
- **可扩展**：新增平台只需添加新的适配器文件，无需修改核心逻辑

## 3. 模块说明 (Module Description)

### 3.1 `danmaku_listener/engines/` — 监听引擎层
**职责**：管理底层监听机制，屏蔽不同技术栈的差异

| 文件 | 功能描述 |
|------|----------|
| `base.py` | 定义 `BaseEngine` 抽象基类，规定 `start()`, `stop()`, `restart()` 等接口 |
| `proxy_engine.py` | 基于 mitmproxy 的代理模式实现，处理系统代理注册、流量拦截 |
| `browser_engine.py` | 基于 Playwright 的浏览器模式实现，管理 BrowserContext 池 |

### 3.2 `danmaku_listener/adapters/` — 平台适配器层
**职责**：将原始数据转换为标准格式，隔离不同平台的协议差异

| 文件 | 功能描述 |
|------|----------|
| `base.py` | 定义 `BaseAdapter` 抽象基类，规定 `parse()` 接口 |
| `douyin.py` | 抖音平台适配器，解析 Protobuf 二进制消息 |
| `generic.py` | 通用平台适配器，执行 JS 脚本提取弹幕文本 |
| `protocols/` | 存放各平台的协议定义文件（.proto, JSON schema） |

### 3.3 `danmaku_listener/bus/` — 消息总线层
**职责**：接收、过滤、格式化、分发弹幕消息

| 文件 | 功能描述 |
|------|----------|
| `event_bus.py` | 异步事件分发中心，支持订阅/发布模式 |
| `message.py` | `DanmakuMessage` 数据模型定义（Pydantic） |
| `dedup_filter.py` | 滑动窗口去重过滤器，防止重复推送 |
| `formatters.py` | 消息格式化工具，确保输出一致性 |

### 3.4 `danmaku_listener/managers/` — 资源管理层
**职责**：管理生命周期有限的外部资源（证书、Cookie、连接）

| 文件 | 功能描述 |
|------|----------|
| `certificate_manager.py` | SSL 证书生成、信任、更新 |
| `cookie_manager.py` | Cookie 文件读写、加密存储 |
| `reconnect_manager.py` | 断线重连策略执行（指数退避） |
| `heartbeat_monitor.py` | 页面/连接健康检查 |

### 3.5 `danmaku_listener/config/` — 配置管理层
**职责**：集中管理所有可配置参数

| 文件 | 功能描述 |
|------|----------|
| `settings.py` | Pydantic Settings 模型，支持环境变量覆盖 |
| `defaults.py` | 默认配置值常量 |

### 3.6 `danmaku_listener/utils/` — 工具函数层
**职责**：提供跨模块使用的通用工具函数

| 文件 | 功能描述 |
|------|----------|
| `platform_parser.py` | 解析 `"platform:room_id"` 格式字符串 |
| `url_validator.py` | 验证直播间 URL 合法性 |
| `logger.py` | Loguru 日志初始化配置 |

## 4. 文件放置规则 (Placement Rules)

### 4.1 新功能开发时的文件放置

| 场景 | 放置位置 | 示例 |
|------|---------|------|
| 新增平台适配器 | `danmaku_listener/adapters/{platform}.py` | `danmaku_listener/adapters/douyu.py` |
| 新增监听引擎 | `danmaku_listener/engines/{name}_engine.py` | `danmaku_listener/engines/websocket_engine.py` |
| 新增消息类型 | `danmaku_listener/bus/message.py` | 在 `DanmakuMessage` 中添加字段 |
| 新增配置项 | `danmaku_listener/config/settings.py` | 在 `Settings` 类中添加字段 |
| 新增工具函数 | `danmaku_listener/utils/{name}.py` | `danmaku_listener/utils/time_helper.py` |

### 4.2 禁止事项
- ❌ 禁止在 `engines/` 中编写平台特定的解析逻辑（应放在 `adapters/`）
- ❌ 禁止在 `adapters/` 中直接操作网络或浏览器（应调用 `engines/`）
- ❌ 禁止跳过抽象基类直接实现具体类（违反开闭原则）
- ❌ 禁止在生产代码中使用 `print()` 调试（应使用 `loguru`）

### 4.3 命名规范
- **模块名**：小写下划线分隔（`proxy_engine.py`）
- **类名**：大驼峰（`ProxyEngine`, `DouyinAdapter`）
- **函数名**：小写下划线分隔（`parse_message()`, `generate_certificate()`）
- **常量**：全大写下划线分隔（`MAX_RETRIES`, `DEFAULT_PORT`）
- **私有成员**：单下划线前缀（`_internal_method()`）

## 5. 导入路径规范

### 5.1 绝对导入优先
```python
# ✅ 正确：绝对导入
from danmaku_listener.engines.proxy_engine import ProxyEngine
from danmaku_listener.adapters.douyin import DouyinAdapter

# ❌ 错误：相对导入（仅在同一模块内允许）
from .proxy_engine import ProxyEngine
```

### 5.2 循环依赖规避
- 如果 A 模块需要引用 B 模块，但 B 也需要引用 A，则抽取公共部分到 `shared/` 或提升层级
- 典型场景：`engines/` 不应直接引用 `adapters/`，两者都依赖 `bus/`
