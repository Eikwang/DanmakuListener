# 代理弹幕捕获引擎 — 功能需求说明书

## 1. 背景与价值

**为什么做**：当前 ProxyEngine 仅有骨架（`_start_proxy` / `_stop_proxy` 为 TODO），无法实际拦截抖音直播间的弹幕流量。用户的浏览器流量经过代理时，代理无法识别、解密、解析 WebSocket 中的 Protobuf 弹幕数据，整个代理模式监听链路断路。

**做成什么样**：用 mitmproxy 替代 DouyinBarrageGrab 中的 Titanium.Web.Proxy，实现完整的代理弹幕捕获闭环——用户调用 `start(["douyin:123456"])` 后，代理自动拦截浏览器与抖音 WebSocket 服务端之间的弹幕流量，实时解码 Protobuf 消息并转换为标准 DanmakuMessage 格式输出。

**关联**：Phase 1.E.3.4（代理引擎实现）、产品概述 §3.1（代理监听引擎）

---

## 2. 范围

### 本次做

- mitmproxy 代理服务器启动/停止（addon 脚本模式，与 asyncio 共存）
- SSL 证书管理（根证书生成、安装到系统信任存储、加载已有证书）
- 系统代理注册/关闭（Windows 注册表，可配置开关）
- 域名白名单 SSL 解密（仅解密 `*webcast*`、`live.douyin.com`、`webcast.amemv.com` 等业务域名）
- 进程过滤（仅拦截 chrome、msedge 等指定浏览器进程的流量）
- WebSocket 连接拦截（识别 `webcast\d+-ws-web-\w+\.douyin\.com` 域名）
- Protobuf + Gzip 消息解码（复用 DouyinBarrageGrab 的 .proto 定义生成 Python 类）
- 消息类型分发 → DanmakuMessage 标准格式转换
- 页面 Hook：CSP 响应头删除、自动播放禁用
- JS Hook：绕过无操作检测（PausePop.js）、强制轮询模式开关
- 断线重连（复用已有 ReconnectManager）

### 本次不做

- HTTP 轮询通道拦截（`/webcast/im/fetch`） — 仅做 WebSocket 通道，轮询降级场景暂不覆盖
- webroomid ↔ roomid 映射和房间信息缓存 — 用户传入 webroomid 即可，不做 Douyin API 调用
- 直播伴侣 Hook（开播/关播事件） — 仅支持浏览器场景
- 弹幕转发 WebSocket 服务端 — 不做 WsBarrageServer，仅通过 EventBus 分发
- 非 Windows 平台适配 — 系统代理注册仅支持 Windows

## 4. 需求详述

### 4.1 核心流程

1. 用户调用 `start(["douyin:123456"])` → 初始化 mitmproxy ProxyServer + 安装 SSL 证书 + 可选注册系统代理
2. 浏览器打开抖音直播页 → 流量经过代理 → 代理按域名白名单决定是否解密 SSL → 仅解密业务域名
3. 代理检测到 WebSocket 连接（`webcast*-ws-web-*.douyin.com`）→ 订阅该连接的后续数据帧
4. WebSocket 数据帧到达 → Protobuf 解码（Gzip 解压如需）→ 按消息类型分发到对应事件
5. ChatMessage / GiftMessage 等 → 转换为 DanmakuMessage → 触发 `on_danmaku` 事件 → 上层应用接收
6. 页面 HTML 响应经过代理 → 删除 CSP 头 → 可选注入脚本 → 浏览器渲染被修改的页面
7. JS 响应经过代理 → 检测并绕过无操作检测 → 可选强制启用轮询模式
8. 用户调用 `stop()` → 关闭 mitmproxy → 恢复系统代理设置 → 状态变为 STOPPED

### 4.2 交互规则

- 系统代理注册需管理员权限：若权限不足，记录警告日志，代理服务器仍正常启动（用户需手动配置浏览器代理）
- 首次运行时证书安装可能弹出系统确认对话框：不自动确认，用户需手动同意
- 进程过滤为白名单机制：仅拦截配置中列出的进程，其余进程的流量直接放行不解密
- 代理端口冲突时：启动失败并抛出明确异常，提示用户修改端口或关闭占用进程

### 4.3 业务规则

| 编号 | 规则 |
|------|------|
| BR-001 | SSL 解密仅对域名白名单生效：`*webcast*`、`live.douyin.com`、`webcast.amemv.com`、`*-webcast-platform.bytetos.com`，其余域名一律不解密 |
| BR-002 | 系统代理注册为可配置开关：`used_proxy=true` 时修改注册表并启动时注册/停止时关闭；`used_proxy=false` 时不触碰注册表 |
| BR-003 | Protobuf 解码按消息类型分发：已知类型（WebcastChatMessage 等 7 种）→ 触发对应事件；未知类型 → 静默忽略，不报错 |
| BR-004 | 重复消息去重：相同 msgId 的消息只触发一次事件（复用 DedupFilter） |
| BR-005 | 进程过滤为白名单：默认包含 `chrome, msedge, QQBrowser, 360se, firefox, 2345Explorer, iexplore`，用户可配置 |

## 5. 验收标准

### 5.1 正常流程 (Happy Path)

- [ ] **AC-001**: 代理服务器启动
  - **Given** 代理服务器未启动
  - **When** 调用 `start(["douyin:123456"])`
  - **Then** mitmproxy 代理服务器在配置的端口启动，ProxyEngine 状态变为 RUNNING

- [ ] **AC-002**: 域名白名单 SSL 解密
  - **Given** 代理服务器已启动且系统代理开关开启
  - **When** 浏览器访问任意 HTTPS 网站
  - **Then** 流量经过代理，仅白名单域名的 SSL 被解密，其余域名直接转发

- [ ] **AC-003**: WebSocket 连接拦截
  - **Given** 代理正在运行
  - **When** 浏览器打开抖音直播间页面，与 `webcast*-ws-web-*.douyin.com` 建立 WebSocket 连接
  - **Then** 代理识别并订阅该 WebSocket 连接，日志记录新的弹幕流地址和 room_id

- [ ] **AC-004**: 弹幕消息解码与分发
  - **Given** WebSocket 连接已建立
  - **When** 抖音服务端推送 WebcastChatMessage 类型的弹幕消息
  - **Then** 代理拦截数据帧，Protobuf 解码成功，触发 `on_danmaku` 事件，DanmakuMessage 的 content 为弹幕文本、message_type 为 "normal"

- [ ] **AC-005**: 礼物消息解码与分发
  - **Given** WebSocket 连接已建立
  - **When** 抖音服务端推送 WebcastGiftMessage 类型的礼物消息
  - **Then** DanmakuMessage 的 message_type 为 "gift"，gift_info 包含礼物名称和数量

- [ ] **AC-006**: CSP 头删除
  - **Given** 浏览器打开了抖音直播页面
  - **When** 代理拦截到该页面的 HTML 响应
  - **Then** 删除 Content-Security-Policy 响应头，页面可执行注入脚本

- [ ] **AC-007**: 进程过滤生效
  - **Given** 代理正在运行且进程过滤器已配置为 `["chrome", "msedge"]`
  - **When** Chrome 发起请求到白名单域名
  - **Then** 代理拦截并解密该流量；非白名单进程的流量不被拦截

- [ ] **AC-008**: 代理停止与系统代理恢复
  - **Given** 代理正在运行且系统代理已注册
  - **When** 调用 `stop()`
  - **Then** 代理服务器停止，系统代理设置恢复为关闭（ProxyEnable=0），状态变为 STOPPED

### 5.2 边界与异常 (Edge & Error Cases)

- [ ] **AC-009**: 证书安装失败降级
  - **Given** 根证书未安装到系统信任存储
  - **When** 代理首次启动，证书安装失败（无管理员权限）
  - **Then** 记录警告日志但不阻止启动，代理服务器正常运行（HTTPS 解密可能失败，用户需手动信任证书）

- [ ] **AC-010**: Protobuf 解码失败容错
  - **Given** WebSocket 连接已建立
  - **When** 收到一个无法解码的 Protobuf 数据帧（如抖音更新了协议）
  - **Then** 记录错误日志但不崩溃，不影响后续消息的处理

- [ ] **AC-011**: Gzip 解压失败容错
  - **Given** WebSocket 连接已建立
  - **When** 收到标记为 Gzip 压缩的数据帧但解压失败
  - **Then** 记录警告日志，跳过该帧，不触发事件

- [ ] **AC-012**: WebSocket 断线重连
  - **Given** WebSocket 连接已建立
  - **When** 抖音 WebSocket 连接意外断开
  - **Then** 代理检测到断开事件，触发 ReconnectManager 进行指数退避重连

- [ ] **AC-013**: 系统代理恢复保障
  - **Given** 系统代理已注册
  - **When** `stop()` 调用时代理服务器已异常退出
  - **Then** 仍然正确关闭系统代理设置（恢复 ProxyEnable=0）

- [ ] **AC-014**: 非白名单域名不解密
  - **Given** 进程过滤器中包含 "chrome"
  - **When** Chrome 浏览器发起 HTTPS 请求到非白名单域名
  - **Then** 代理不解密 SSL（直接转发），避免性能开销

- [ ] **AC-015**: JS 无操作检测绕过
  - **Given** 页面 Hook 已启用
  - **When** 拦截到 PausePop.js 中的无操作检测代码
  - **Then** 将条件替换为 `if(false){`，绕过检测

### 5.3 业务规则验证 (Business Rules)

- [ ] **AC-016**: SSL 解密白名单约束 ← BR-001
  - **Given** 代理正在运行
  - **When** 对任意域名进行 SSL 解密判断
  - **Then** 仅白名单中的域名返回 True，其余返回 False

- [ ] **AC-017**: 系统代理可配置开关 ← BR-002
  - **Given** 系统代理开关为 `used_proxy=false`
  - **When** 代理启动和停止
  - **Then** 不修改 Windows 注册表中的系统代理设置

- [ ] **AC-018**: 未知消息类型静默忽略 ← BR-003
  - **Given** WebSocket 连接已建立
  - **When** Protobuf 解码出一条消息，其 method 字段不在已知类型列表中
  - **Then** 不触发任何事件回调，不记录错误日志

- [ ] **AC-019**: 重复消息去重 ← BR-004
  - **Given** WebSocket 连接已建立
  - **When** 同一条弹幕消息（相同 msgId）被重复接收
  - **Then** DedupFilter 过滤重复，上层只收到一次 on_danmaku 事件
