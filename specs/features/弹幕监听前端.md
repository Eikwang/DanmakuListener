# 弹幕监听前端 — 功能需求说明书

## 1. 背景与价值

**为什么做**：当前 DanmakuListener 项目存在两套独立的代码——旧的 app.py 单体服务和新的 danmaku_listener Python 包。app.py 包含大量已废弃的逻辑（直播伴侣客户端、浏览器监控、脚本管理等），且未接入新开发的代理引擎能力。用户需要一个简洁的前端来测试和验证新后端的功能，同时清理掉所有不再需要的旧代码。

**做成什么样**：一个轻量级 Web 前端，通过 WebSocket + HTTP API 与 danmaku_listener 后端通信，提供房间管理、弹幕实时展示、代理状态监控、关键词屏蔽和系统代理控制功能。

**关联**：DanmakuListener 重构 Phase 3 — 前后端分离与旧代码清理

---

## 2. 范围

### 本次做

- 独立 Web 前端服务（aiohttp）
- 房间管理（添加/删除/启动/停止监听）
- 弹幕实时展示（WebSocket 推送）
- 代理状态监控（引擎运行状态、连接数）
- 关键词屏蔽（过滤特定关键词的弹幕）
- 系统代理控制（开启/关闭 Windows 系统代理）
- 简洁的单页面 UI

### 本次不做

- 历史消息存储和查询 — 后端不存储弹幕数据，前端也不做本地持久化
- 直播伴侣客户端管理 — 旧逻辑，已被代理模式替代
- 浏览器监控管理 — 旧逻辑，Playwright 模式由 danmaku_listener 内部管理
- 脚本注入管理 — 旧逻辑，不再需要手动注入脚本
- 重启管理器 — 旧逻辑，与新架构无关
- 多用户支持 — 单机工具，无需认证授权
- 配置管理界面 — 使用配置文件即可，不需要动态修改

## 4. 需求详述

### 4.1 核心流程

> 这里只描述主线路径的全局视角——用户从哪里开始、经过哪些关键节点、到哪里结束。每个节点的细节由 AC 承载。

1. **启动服务** — 启动后端 danmaku_listener 和前端 Web 服务
2. **查看状态** — 打开前端页面，查看后端连接状态和当前代理状态
3. **添加房间** — 输入 `platform:room_id` 格式的房间标识，添加到监听列表
4. **启动监听** — 点击"启动监听"按钮，后端启动对应的代理引擎或浏览器引擎
5. **开启代理** — 点击"开启系统代理"，后端修改 Windows 注册表设置代理
6. **观看弹幕** — 在浏览器中打开直播间，弹幕实时显示在前端页面
7. **管理房间** — 可随时添加新房间、删除房间、暂停/恢复单个房间监听
8. **停止监听** — 点击"全部停止"，关闭所有监听并恢复系统代理

### 4.2 交互规则

- 添加房间时，输入框失焦后实时校验格式，错误提示显示在输入框下方
- 启动监听按钮在操作执行期间置灰，防止重复提交
- 系统代理开关采用 Toggle 按钮样式，状态变化有明显视觉反馈
- 弹幕区域自动滚动到最新消息，用户可手动暂停滚动
- 网络断开时，前端显示明显的"连接断开"提示，并尝试自动重连
- 所有操作都有相应的成功/失败提示

### 4.3 业务规则

| 编号 | 规则 |
|------|------|
| BR-001 | 房间格式必须为 `platform:room_id`，其中 platform 为 douyin/douyu/bilibili/kuaishou/taobao/weixin，room_id 为非空字符串 |
| BR-002 | 同时监听的房间数量上限为 10 个 |
| BR-003 | 弹幕延迟从后端拦截到前端显示的时间差 < 1 秒 |
| BR-004 | 系统代理端口固定为 127.0.0.1:8827 |
| BR-005 | 关键词屏蔽仅对普通弹幕生效，不影响礼物、点赞等其他消息类型 |
| BR-006 | 停止所有监听时，必须同时恢复系统代理为关闭状态 |

## 5. 验收标准

> AC 是这份文档的核心交付物。后续的技术方案、任务拆分、TDD 测试用例全部从这里派生。

### 5.1 正常流程 (Happy Path)

- [ ] **AC-001**: 前端页面加载与状态显示
  - **Given** 后端服务已启动
  - **When** 用户打开前端页面
  - **Then** 页面正常加载，显示空的房间列表和当前代理状态（启用/禁用）

- [ ] **AC-002**: 添加房间
  - **Given** 前端页面已加载
  - **When** 用户输入 `douyin:123456` 并点击"添加房间"
  - **Then** 房间出现在列表中，状态为"未启动"，显示平台标签和房间 ID

- [ ] **AC-003**: 启动房间监听
  - **Given** 房间已添加，状态为"未启动"
  - **When** 用户点击该房间的"启动监听"按钮
  - **Then** 后端启动对应的引擎，前端显示状态变为"运行中"，按钮变为"停止监听"

- [ ] **AC-004**: 开启系统代理
  - **Given** 代理引擎已运行
  - **When** 用户点击"开启系统代理"按钮
  - **Then** Windows 系统代理设置为 127.0.0.1:8827，前端显示"已启用"，按钮变为"关闭代理"

- [ ] **AC-005**: 弹幕实时显示
  - **Given** 系统代理已开启，浏览器正在访问抖音直播间
  - **When** 直播间产生弹幕
  - **Then** 弹幕实时显示在前端页面上，包含用户名、内容、时间戳

- [ ] **AC-006**: 全部停止
  - **Given** 正在监听多个房间
  - **When** 用户点击"全部停止"按钮
  - **Then** 所有房间状态变为"已停止"，系统代理恢复为关闭状态

- [ ] **AC-007**: 关键词屏蔽
  - **Given** 正在接收弹幕
  - **When** 用户添加屏蔽关键词"广告"
  - **Then** 包含"广告"的弹幕不再显示，其他弹幕正常显示

### 5.2 边界与异常 (Edge & Error Cases)

- [ ] **AC-008**: 无效房间格式
  - **Given** 用户输入无效房间格式
  - **When** 点击"添加房间"
  - **Then** 前端显示错误提示"格式不正确，应为 platform:room_id"，房间不被添加

- [ ] **AC-009**: 重复启动
  - **Given** 房间已在运行中
  - **When** 用户再次点击"启动监听"
  - **Then** 前端忽略操作或提示"该房间已在监听中"

- [ ] **AC-010**: 后端连接失败
  - **Given** 后端服务未启动或连接断开
  - **When** 用户打开前端页面
  - **Then** 页面显示"无法连接到后端服务"提示，并提供重试按钮

- [ ] **AC-011**: 关闭系统代理
  - **Given** 系统代理已开启
  - **When** 用户点击"关闭系统代理"按钮
  - **Then** Windows 系统代理恢复原状，前端显示"已禁用"

- [ ] **AC-012**: WebSocket 断线重连
  - **Given** 正在监听房间
  - **When** 网络中断导致 WebSocket 断开
  - **Then** 前端显示"连接断开"提示，并在 3 秒内尝试自动重连

- [ ] **AC-013**: 重复房间 ID
  - **Given** 房间列表中已存在 room_id=123456
  - **When** 用户再次添加 `douyin:123456`
  - **Then** 前端提示"该房间已存在"或自动合并为同一房间

### 5.3 业务规则验证 (Business Rules)

- [ ] **AC-014**: 弹幕延迟 < 1 秒 ← BR-003
  - **Given** 后端正在拦截弹幕
  - **When** 计算从拦截到前端显示的时间差
  - **Then** 时间差 < 1 秒

- [ ] **AC-015**: 多房间弹幕按时间排序 ← 无特定 BR，但为隐含规则
  - **Given** 同时监听多个房间
  - **When** 任意房间收到弹幕
  - **Then** 弹幕按时间顺序显示，不区分来源房间

- [ ] **AC-016**: 代理设置权限错误处理 ← BR-004
  - **Given** 后端执行注册表修改失败（如权限不足）
  - **When** 用户点击"开启系统代理"
  - **Then** 前端显示错误提示"代理设置失败，请检查权限"

- [ ] **AC-017**: 端口冲突处理 ← BR-004
  - **Given** 代理端口 8827 已被占用
  - **When** 用户启动监听
  - **Then** 前端显示错误提示"代理端口被占用，请检查配置"

- [ ] **AC-018**: 清空屏蔽关键词 ← BR-005
  - **Given** 用户已设置关键词屏蔽
  - **When** 用户清空屏蔽列表
  - **Then** 所有弹幕正常显示
