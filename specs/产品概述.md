# 产品概述

## 1. 项目愿景 (Vision)
> 为直播系统集成者提供一套**高性能、易集成、跨平台**的弹幕监听解决方案，通过代理模式与浏览器模式的混合架构，从根本上解决传统方案的内存泄漏问题，让弹幕数据获取变得简单可靠。

## 2. 核心价值 (Value Proposition)
*   **用户价值**：
    *   **开箱即用的集成体验**：作为 Python 包导入即可使用，无需关心底层实现细节
    *   **稳定的性能表现**：代理模式下内存占用稳定可控（~50MB），弹幕延迟 < 100ms
    *   **灵活的平台扩展**：支持主流平台（抖音、斗鱼、B站）及长尾平台（淘宝、视频号）全覆盖
*   **商业/技术价值**：
    *   **降低维护成本**：模块化设计，单一职责，便于独立测试和升级
    *   **提升系统稳定性**：从根源上解决 Chromium 注入脚本导致的内存累积问题
    *   **加速产品迭代**：标准化的数据格式输出，减少上层应用的适配工作量

## 3. 核心板块 (Core Modules)

### 3.1 代理监听引擎 (Proxy Engine)
*   **描述**：基于网络层流量拦截的高性能弹幕抓取引擎，适用于支持 WebSocket/HTTP 协议的主流直播平台
*   **关键特性**：
    *   **进程过滤机制**：仅监听指定进程的网络流量（如 Chrome、Edge、直播伴侣等），避免无关请求干扰
    *   **域名白名单优化**：智能识别并解密必要的业务域名，最小化 CPU 开销
    *   **双通道数据获取**：同时支持 WebSocket 实时推送和 HTTP 轮询降级模式
    *   **Protobuf 协议解析**：高效解码抖音等平台的二进制消息格式

### 3.2 Playwright 浏览器引擎 (Browser Engine)
*   **描述**：基于 Playwright 单实例多页面架构的备用监听方案，用于不支持代理模式或协议复杂的小众平台
*   **关键特性**：
    *   **资源隔离设计**：每个直播间使用独立的 BrowserContext，防止状态污染和内存泄漏
    *   **Cookie 持久化管理**：自动保存和加载登录状态，避免重复认证
    *   **脚本注入执行**：支持动态加载和执行平台特定的监听脚本
    *   **心跳保活机制**：定期检测页面健康状态，异常时自动重启

### 3.3 统一消息总线 (Unified Message Bus)
*   **描述**：负责接收来自不同引擎的原始弹幕数据，进行标准化转换和事件分发的核心组件
*   **关键特性**：
    *   **标准化格式输出**：所有平台弹幕统一转换为 `{platform, room_id, user_name, content, timestamp, message_type, gift_info}` 格式
    *   **去重处理**：基于消息 ID 的滑动窗口去重，防止重复推送
    *   **事件驱动架构**：提供 `on_danmaku`, `on_error`, `on_reconnect`, `on_status_change` 四种事件回调
    *   **异步非阻塞**：基于 asyncio 的事件循环，确保高并发下的性能表现

### 3.4 Python 包接口层 (Package Interface)
*   **描述**：对外暴露的简洁 API 接口，支持多种生命周期管理模式
*   **关键特性**：
    *   **上下文管理器支持**：支持 `with DanmakuListener() as listener:` 语法，自动释放资源
    *   **显式控制模式**：提供 `start()`, `stop()` 方法供手动调用
    *   **配置驱动**：通过 JSON/YAML 配置文件灵活调整参数
    *   **日志分级**：开发环境开启 DEBUG 级别日志，生产环境可关闭以减少开销

## 4. 目标用户 & 核心场景 (User & Scenes)

### 4.1 目标用户
*   **直播系统开发者**：正在构建或维护包含弹幕功能的直播平台的技术人员，他们需要将弹幕监听能力集成到自己的系统中
*   **数据分析团队**：需要实时采集直播间互动数据用于业务分析、舆情监控或运营决策的人员
*   **自动化工具开发者**：希望基于弹幕数据开发自动化互动工具（如语音播报、弹幕游戏）的个人开发者或小团队

### 4.2 核心场景 (Key Use Cases)
*   **场景 1**：直播系统开发者在 Python 项目中引入 `danmaku_listener` 包，通过一行代码启动对多个直播间的监听，实时获取标准化的弹幕数据用于后续处理。
*   **场景 2**：数据分析团队配置监听任务，持续采集特定主播的直播间弹幕和礼物数据，生成可视化报表用于评估主播影响力。
*   **场景 3**：自动化工具开发者利用弹幕事件触发自定义逻辑，例如当检测到特定关键词时自动发送欢迎消息或触发特效。

## 5. 关键业务流程 (Core Workflows)

### 流程 A：代理模式监听流程（抖音平台）
```
用户调用 start(["douyin:123456"])
    ↓
初始化代理服务器 (Titanium.Web.Proxy / mitmproxy)
    ↓
注册系统代理 (127.0.0.1:8827)
    ↓
浏览器打开直播间 → 流量经过代理
    ↓
拦截 WebSocket 连接 (wss://webcast*-ws-web-*.douyin.com)
    ↓
解析 Protobuf 消息 + Gzip 解压
    ↓
提取 ChatMessage / GiftMessage / LikeMessage...
    ↓
转换为标准格式 → 触发 on_danmaku 事件
    ↓
上层应用接收并处理
```

### 流程 B：Playwright 模式监听流程（其他平台）
```
用户调用 start(["taobao:789012"])
    ↓
启动 Playwright 浏览器实例
    ↓
创建 BrowserContext (隔离环境)
    ↓
加载 Cookie 恢复登录状态
    ↓
导航至直播间页面
    ↓
注入监听脚本 (通用平台.js)
    ↓
监听 DOM 变化 → 提取弹幕文本
    ↓
转换为标准格式 → 触发 on_danmaku 事件
    ↓
上层应用接收并处理
```

## 6. 验收标准 (Acceptance Criteria)

### Phase 1 验收标准（代理模式 - 抖音平台）
*   **功能完备性**：
    *   ✅ 成功启动代理服务器并注册系统代理
    *   ✅ 能够拦截并解析抖音直播间的 WebSocket 消息
    *   ✅ 正确识别并分类以下消息类型：普通弹幕、礼物、点赞、关注、进房、统计、粉丝团
    *   ✅ 支持同时监听至少 10 个直播间
    *   ✅ 断线重连机制生效（心跳超时 → 立即重试 3 次 → 失败后通知上层）
*   **技术指标**：
    *   ✅ 弹幕延迟 < 1 秒
    *   ✅ 内存占用稳定，运行 24 小时后无明显增长
    *   ✅ 代码覆盖率 > 70%
    *   ✅ 单元测试全部通过

### Phase 2 验收标准（Playwright 模式集成）
*   **功能完备性**：
    *   ✅ Playwright 浏览器实例正常启动和关闭
    *   ✅ BrowserContext 隔离机制生效，无状态污染
    *   ✅ Cookie 持久化功能正常工作
    *   ✅ 能够加载并执行自定义监听脚本
    *   ✅ 心跳保活机制有效，页面崩溃后自动恢复
*   **技术指标**：
    *   ✅ 单个直播间内存占用 < 200MB
    *   ✅ 页面加载时间 < 3 秒
    *   ✅ 脚本执行错误率 < 1%

## 7. 约束条件 (Constraints)
*   **性能约束**：
    *   弹幕延迟容忍度 < 1 秒
    *   同时监听直播间数量上限为 10 个
    *   重连策略：立即重试 3 次，失败后通知上层应用
*   **技术约束**：
    *   必须作为 Python 包被导入使用，不提供独立 Web 服务
    *   时间戳精度为秒级
    *   Cookie 存储复用现有 `cookie/` 目录结构
    *   资源释放范围：关闭所有 BrowserContext/Page
*   **兼容性约束**：
    *   支持 Windows 操作系统（主要开发环境）
    *   Python 版本 >= 3.10
    *   需兼容现有的直播系统架构（同样是 Python 构建）

## 8. 项目边界 (Out of Scope)
*   **Phase 1 不做事项**：
    *   ❌ 斗鱼、B站等其他平台的代理模式适配（将在 Phase 3 完成）
    *   ❌ 淘宝、视频号等平台的 Playwright 脚本开发（将在 Phase 2 完成）
    *   ❌ Web 界面或图形化配置工具
    *   ❌ 消息持久化存储（数据库写入、文件记录等）
*   **长期不做事项**：
    *   ❌ 移动端支持（iOS/Android App）
    *   ❌ 分布式部署或集群管理能力
    *   ❌ 弹幕内容的 AI 分析或情感识别功能
    *   ❌ 主动发送弹幕或礼物的能力（仅监听）
