# DanmakuListener 开发规范

本文档定义 DanmakuListener 项目的代码风格、命名约定、Git 工作流和 AI 协作协议，确保代码库长期可维护。

## 1. 语言与运行时要求

| 维度 | 规格 |
|------|------|
| **语言** | Python 3.10+（必须使用类型注解） |
| **运行时** | Windows 11（主要开发环境），支持跨平台 |
| **包管理器** | Poetry >= 1.7（禁止使用 pip 直接安装） |
| **类型检查** | mypy >= 1.8，严格模式 |
| **异步编程** | asyncio 原生支持，禁止使用多线程除非必要 |

## 4. Python 特定规范

### 4.1 类型注解

**所有公共函数必须有完整的类型注解**：

```python
# ✅ 正确：完整类型注解
async def parse_message(raw_data: bytes) -> Optional[DanmakuMessage]:
    """解析原始消息为标准格式"""
    ...

def calculate_delay(attempt: int) -> float:
    """计算重连延迟时间"""
    return BASE_DELAY * (2 ** attempt)

# ❌ 错误：缺少类型注解
async def parse_message(raw_data):  # 缺少返回类型
    ...
```

### 4.2 导入顺序

```python
# 标准库导入
import asyncio
import json

# 第三方库导入
```

### 4.3 避免的写法

#### 4.3.1 避免使用 any

```python
# ❌ 错误：使用 any
def process(data: any) -> None:
    ...

# ✅ 正确：使用具体类型或 Union
def process(data: dict[str, Any]) -> None:
    ...

# 如果确实需要任意类型，使用 TypeAlias 并添加注释
AnyData = object  # 表示任意对象，用于特殊场景
```

#### 4.3.2 避免裸 except

```python
# ❌ 错误：捕获所有异常
try:
    await connection.send()
except:  # 会捕获所有异常，包括 KeyboardInterrupt
    pass

# ✅ 正确：捕获具体异常
try:
    await connection.send()
except (ConnectionError, TimeoutError) as e:
    logger.warning(f"连接失败: {e}")
    raise

# ✅ 正确：需要捕获所有异常时记录日志
try:
    await connection.send()
except Exception as e:
    logger.error(f"未预期的错误: {e}", exc_info=True)
    raise
```

#### 4.3.3 避免使用 print 调试

```python
# ❌ 错误：使用 print 调试
print(f"收到消息: {data}")

# ✅ 正确：使用 loguru
logger.debug(f"收到消息: {data}")
logger.info(f"启动代理服务器，端口: {port}")
logger.warning(f"重连失败，第 {attempt} 次尝试")
logger.error(f"解析消息失败: {e}")
```

#### 4.3.4 避免 mutable default arguments

```python
# ❌ 错误：可变默认参数
def process_messages(messages: list = []):  # 每次调用共享同一个列表
    ...

# ✅ 正确：使用 None 作为默认值
def process_messages(messages: Optional[list] = None):
    if messages is None:
        messages = []
    ...

# ✅ 正确：使用类型注解和工厂函数
def process_messages(messages: list[DanmakuMessage] | None = None) -> None:
    messages = messages or []
    ...
```

#### 4.3.5 避免长函数

```python
# ❌ 错误：函数过长（超过 50 行）
async def start_monitoring(self, room_id: str):
    # 初始化代理...
    # 注册回调...
    # 启动心跳...
    # 处理消息...
    # 错误处理...
    # 清理资源...
    # ... 还有更多代码

# ✅ 正确：拆分为多个小函数
async def start_monitoring(self, room_id: str):
    await self._initialize_proxy()
    await self._register_callbacks()
    await self._start_heartbeat()

async def _initialize_proxy(self):
    ...

async def _register_callbacks(self):
    ...

async def _start_heartbeat(self):
    ...
```

### 4.4 Pydantic 模型规范

```python
# ✅ 正确：使用 Pydantic v2 特性
from pydantic import BaseModel, Field, field_validator

class DanmakuMessage(BaseModel):
    platform: str
    room_id: str
    user_name: str
    content: str
    timestamp: int
    message_type: Literal["normal", "gift", "system"]
    gift_info: Optional[GiftInfo] = None

    @field_validator("timestamp")
    @classmethod
    def validate_timestamp(cls, v: int) -> int:
        if v < 0:
            raise ValueError("timestamp must be positive")
        return v

    model_config = {"extra": "forbid"}  # 禁止额外字段

# ❌ 错误：使用 dict 代替 Pydantic
class DanmakuMessage:
    def __init__(self, data: dict):
        self.data = data  # 没有类型验证
```

## 5. 异步编程规范

### 5.1 async/await 使用

```python
# ✅ 正确：使用 async/await
async def fetch_messages(room_id: str) -> list[DanmakuMessage]:
    data = await self._load_data(room_id)
    return self._parse(data)

# ❌ 错误：混用同步和异步
async def fetch_messages(room_id: str):
    data = self._load_data_sync(room_id)  # 阻塞事件循环
    return self._parse(data)
```

### 5.2 异步上下文管理器

```python
# ✅ 正确：使用 asynccontextmanager
from contextlib import asynccontextmanager

@asynccontextmanager
async def managed_connection(host: str, port: int):
    conn = await create_connection(host, port)
    try:
        yield conn
    finally:
        await conn.close()

# 使用
async with managed_connection("localhost", 8827) as conn:
    await conn.send(data)
```

### 5.3 Task 管理

```python
# ✅ 正确：使用 TaskGroup（Python 3.11+）
async def start_all_rooms(self, rooms: list[str]):
    async with asyncio.TaskGroup() as tg:
        for room_id in rooms:
            tg.create_task(self._monitor_room(room_id))
```

## 7. Git 工作流

### 7.1 分支策略

采用简化的 Trunk-Based Development（适合独立开发者）：

```
main (生产分支)
  │
  ├── feature/add-douyu-adapter    # 新功能分支
  ├── fix/memory-leak-fix          # Bug 修复分支
  └── refactor/extract-engines     # 重构分支
```

| 规则 | 说明 |
|------|------|
| **主分支** | `main`，始终可部署 |
| **功能分支** | 从 `main` 创建，完成后合并回 `main` |
| **分支生命周期** | 不超过 3 天 |
| **合并方式** | Squash Merge（保持提交历史清晰） |

### 7.2 分支命名规范

```
<type>/<short-description>
```

| 类型 | 用途 | 示例 |
|------|------|------|
| `feat/` | 新功能 | `feat/add-douyu-adapter` |
| `fix/` | Bug 修复 | `fix/memory-leak-on-stop` |
| `refactor/` | 重构 | `refactor/extract-engine-base` |
| `docs/` | 文档更新 | `docs/update-readme` |
| `chore/` | 构建/配置 | `chore/upgrade-deps` |
| `test/` | 测试相关 | `test/add-proxy-integration` |

### 7.3 提交信息规范 (Conventional Commits)

所有 Git 提交信息**必须**遵循 Conventional Commits 格式：

```
<type>(<scope>): <subject>

[body]

[footer]
```

#### 类型 (type)

| 类型 | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(proxy): add domain whitelist filtering` |
| `fix` | Bug 修复 | `fix(browser): resolve cookie loading failure` |
| `refactor` | 重构（不改变功能） | `refactor(bus): extract dedup logic to separate module` |
| `style` | 代码格式调整 | `style: format code with black` |
| `docs` | 文档变更 | `docs: update API documentation` |
| `test` | 测试相关 | `test(proxy): add unit tests for certificate manager` |
| `chore` | 构建/工具/依赖 | `chore: upgrade mitmproxy to 10.0` |
| `perf` | 性能优化 | `perf(proxy): reduce memory usage by 30%` |

#### 作用域 (scope)

| scope | 对应范围 |
|-------|---------|
| `proxy` | 代理引擎模块 |
| `browser` | 浏览器引擎模块 |
| `bus` | 消息总线模块 |
| `adapter` | 平台适配器模块 |
| `config` | 配置管理模块 |
| `manager` | 资源管理器模块 |
| `core` | 核心入口与配置 |

#### 提交信息规则

- **subject**：英文、小写开头、不超过 72 字符、不加句号
- **body**：解释**为什么**这样做，不是**做了什么**
- **footer**：Issue 引用格式 `Closes #123` 或 `Refs #456`

#### 示例

```
feat(proxy): add domain whitelist filtering

仅解密必要的业务域名，减少 CPU 开销约 80%。
通过正则匹配 webcast* 域名，避免全量解密导致的性能问题。

Closes #123
```

```
fix(browser): resolve cookie loading failure on Windows

Windows 路径分隔符导致 Cookie 文件读取失败。
改用 pathlib.Path 处理路径，确保跨平台兼容性。

Refs #456
```

## 8. 代码注释规范

### 8.1 何时写注释

| 需要注释 | 不需要注释 |
|----------|-----------|
| 复杂的业务逻辑（如抖音协议解析算法） | 显而易见的代码（如 `x += 1`） |
| 非显而易见的设计决策（如选择 mitmproxy 而非 Titanium） | Pydantic 模型字段（已有类型注解） |
| 临时解决方案或妥协（标记 HACK） | 公共 API 的 docstring（必需） |
| 潜在的副作用或陷阱（如内存泄漏风险） | 简单的 getter/setter |
| TODO/FIXME 待办事项 | 已废弃的代码（应直接删除） |

### 8.2 注释风格

```python
# ✅ 解释 "为什么"
# 抖音 WebSocket 消息使用 Gzip 压缩，需要先解压再解析
raw_data = self._decompress(payload)

# ❌ 描述 "做了什么"
# 解压数据
raw_data = self._decompress(payload)
```

### 8.3 Docstring 规范

## 9. 错误处理规范

### 9.1 统一错误类型

```python
# danmaku_listener/errors.py
from enum import Enum

class ErrorType(Enum):
    NETWORK_ERROR = "network_error"
    PARSE_ERROR = "parse_error"
    AUTH_ERROR = "auth_error"
    RESOURCE_ERROR = "resource_error"
    UNKNOWN_ERROR = "unknown_error"

class DanmakuError(Exception):
    """弹幕监听器基础异常类"""

    def __init__(
        self,
        message: str,
        error_type: ErrorType = ErrorType.UNKNOWN_ERROR,
        room_id: Optional[str] = None,
        original_exception: Optional[Exception] = None,
    ):
        self.message = message
        self.error_type = error_type
        self.room_id = room_id
        self.original_exception = original_exception
        super().__init__(message)
```

### 9.2 错误处理原则

```python
# ✅ 正确：捕获具体异常并转换
try:
    await browser.launch()
except Exception as e:
    raise DanmakuError(
        f"浏览器启动失败: {e}",
        error_type=ErrorType.RESOURCE_ERROR,
        original_exception=e,
    ) from e

# ✅ 正确：向上传播错误，由上层决定如何处理
async def monitor_room(self, room_id: str):
    try:
        await self._start_engine(room_id)
    except DanmakuError:
        # 已经记录日志，直接抛出让上层处理
        raise
    except Exception as e:
        # 未知异常包装后抛出
        raise DanmakuError(
            f"监控房间 {room_id} 失败",
            error_type=ErrorType.UNKNOWN_ERROR,
            room_id=room_id,
            original_exception=e,
        ) from e

# ❌ 错误：吞掉异常
try:
    await browser.launch()
except Exception:
    pass  # 永远不要这样做！
```

### 9.3 用户提示规则

- **永远不在日志中暴露敏感信息**（密码、Token、Cookie）
- **向上层传递结构化错误**，由上层决定如何展示给用户
- **关键操作失败必须记录日志**，即使上层会处理

### 11.2 依赖审查

引入新依赖前必须评估：

| 评估项 | 标准 |
|--------|------|
| **必要性** | 是否无法用现有库实现？ |
| **成熟度** | 是否有活跃维护、足够多的 stars？ |
| **体积** | 是否会显著增加包大小？ |
| **许可证** | 是否符合项目开源许可证？ |
| **替代方案** | 是否有更轻量的替代方案？ |

### 11.3 版本锁定

- **锁文件必须提交**：`poetry.lock` 必须纳入 Git 管理
- **升级策略**：
  - 补丁版本：自动升级（`^1.0.0` → `1.0.1`）
  - 次版本：手动测试后升级（`^1.0.0` → `1.1.0`）
  - 主版本：必须修改代码适配（`^1.0.0` → `2.0.0`）

## 13. AI 协作协议

> 本节定义 AI 辅助开发时必须遵守的规则，确保 AI 生成的代码与人工代码保持一致性。

### 13.1 AI 写代码前必读

| 文档 | 目的 |
|------|------|
| `specs/产品概述.md` | 理解项目愿景和核心价值 |
| `specs/技术栈.md` | 确认技术选型和依赖版本 |
| `specs/项目结构.md` | 理解目录结构和模块划分 |
| `specs/features/DanmakuListener重构_技术方案.md` | 了解详细设计和技术决策 |
| `specs/开发规范.md`（本文件） | 遵循代码风格和命名约定 |
| 相关模块的现有代码 | 理解当前实现，保持一致性 |

### 13.2 AI 写代码的规则

| 规则 | 说明 |
|------|------|
| **读后写** | 修改文件前必须先读取该文件，了解现有实现 |
| **最小改动** | 只修改任务要求的部分，不做"顺便优化"或重构 |
| **不猜版本** | 安装依赖时使用 Poetry 获取最新版，不手写版本号 |
| **不引入新依赖** | 除非任务明确要求，否则不添加新的第三方库 |
| **不写无意义注释** | 不写复述代码的注释（如 `# 设置 x = 1`） |
| **不创建多余文件** | 不主动创建文档或配置文件，除非任务要求 |
| **遵循现有模式** | 相同类型的代码必须遵循已有文件的写法 |
| **提交信息规范** | 严格遵循 Conventional Commits 格式 |
| **类型注解完整** | 所有公共函数必须有完整的类型注解 |
| **使用 loguru** | 禁止使用 print()，必须使用 loguru 日志 |

### 13.3 AI 写完代码后必做

| 步骤 | 操作 |
|------|------|
| **1. 类型检查** | 运行 `mypy danmaku_listener/` 确认无类型错误 |
| **2. Lint 检查** | 运行 `ruff check danmaku_listener/` 确认无 Lint 错误 |
| **3. 格式化检查** | 运行 `black --check danmaku_listener/` 确认格式正确 |
| **4. 依赖方向** | 确认没有违反目录结构中的依赖方向原则 |
| **5. 环境变量** | 如有新增，同步更新 `.env.example` |
| **6. 测试覆盖** | 为核心逻辑添加单元测试 |

### 13.4 错题本机制

当 AI 生成的代码出现问题时，在 `specs/ai-mistakes.md` 中记录：

| 记录项 | 说明 |
|--------|------|
| **错误类型** | 类型错误 / 逻辑错误 / 规范违规 / 依赖错误 |
| **错误描述** | 具体出了什么问题 |
| **根因分析** | 为什么会犯这个错 |
| **正确做法** | 下次应该怎么做 |

**示例记录**：

```markdown
## 错误 #001

**日期**: 2026-07-25
**错误类型**: 规范违规
**错误描述**: 使用了 print() 而不是 loguru
**根因分析**: AI 未遵循开发规范第 4.3.3 条
**正确做法**: 使用 `logger.info()` 替代 `print()`
```

## 15. 安全编码规范

| 类别 | 规则 |
|------|------|
| **输入校验** | 所有外部输入（房间 ID、URL、消息内容）必须验证格式和长度 |
| **注入防护** | Protobuf 解析使用官方库，不使用 eval() 或 pickle |
| **密钥管理** | Cookie 文件加密存储，日志中遮蔽敏感信息 |
| **文件操作** | 禁止任意文件写入，Cookie 目录限制在 `cookie/` 内 |
| **网络访问** | 代理端口绑定 127.0.0.1，禁止外部访问 |
| **认证检查** | 证书自动生成并信任，但需用户确认授权 |
| **资源限制** | 同时监听房间数上限 10 个，防止资源耗尽 |
| **错误处理** | 不向用户暴露内部错误堆栈，仅记录日志 |
