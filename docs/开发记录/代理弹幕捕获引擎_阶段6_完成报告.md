**实现文件**：
- `danmaku_listener/listener.py`（ProxyEngine 单例 + 消息路由改造）
- `tests/integration/test_proxy_danmaku.py`（新增集成测试）

**核心改造**：

1. **ProxyEngine 单例模式**：
   - `_get_engine("proxy")` 不再每次创建新实例，改为返回 `self._proxy_engine` 单例
   - 新增 `_proxy_engine` 属性，`__init__` 中初始化为 `None`
   - `stop()` 时清空 `_proxy_engine = None`
   - 两个 douyin 房间共享同一 ProxyEngine 实例 → AC-001

2. **消息路由改造**（`_handle_raw_message`）：
   - 新增代理模式消息格式支持：`{type, room_id, method, payload, msg_id, platform}`
   - `type="danmaku"` → 构造 `DecodedMessage(method, payload, msg_id)` → 传给 DouyinAdapter.parse()
   - `type="ws_connected"/"ws_disconnect"/"reconnect_success"` → 状态事件，不转发到适配器
   - 浏览器模式消息（`raw_data` 字段）保持原有路径不变
   - 去重检查统一使用 `msg_id` → AC-019

3. **端到端数据流**：
   ```
   DanmakuAddon.websocket_message()
   → ProtobufDecoder.decode() → DecodedMessage
   → ProxyEngine._emit_message({type:"danmaku", method, payload, msg_id, platform})
   → DanmakuListener._handle_raw_message()
   → DecodedMessage 构造 → DouyinAdapter.parse()
   → DanmakuMessage → EventBus.publish("danmaku")
   → on_danmaku 回调
   ```

## 技术决策记录

1. **ProxyEngine 单例 vs 每次创建**：技术方案明确要求 ProxyEngine 单例（mitmproxy 只需启动一次，多房间共享）。实现为 `self._proxy_engine` 属性，`_get_engine("proxy")` 返回同一实例
2. **消息路由双格式支持**：`_handle_raw_message` 需同时支持代理模式（`DecodedMessage` 格式）和浏览器模式（`raw_data` 格式）。通过 `type` 字段区分：`type="danmaku"` → 代理模式，无 `type` 或 `type` 为其他 → 浏览器模式
3. **DecodedMessage 构造位置**：在 `_handle_raw_message` 中构造 `DecodedMessage` 而非在 ProxyEngine 中，因为 ProxyEngine 是通用引擎，不应依赖 Protobuf 解码器的数据结构
4. **状态事件过滤**：`ws_connected`/`ws_disconnect`/`reconnect_success` 等状态事件不转发到适配器，仅在日志中记录
