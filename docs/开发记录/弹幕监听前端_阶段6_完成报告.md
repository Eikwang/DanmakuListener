## 完成任务

### Task-10: 关键词屏蔽

**实现文件**：
- `web/bridge.py`（`get_keywords`、`add_keyword`、`remove_keyword`、`toggle_keyword_filter`）
- `web/app.py`（`api_get_keywords`、`api_add_keyword`、`api_remove_keyword`、`api_toggle_keyword_filter` 路由）

**核心实现**：

1. **`get_keywords()`**：
   - 返回 `{"keywords": [...], "enabled": bool}`
   - 复制列表避免外部修改

2. **`add_keyword(keyword)`**：
   - 长度校验：超过 50 字符抛 ValueError → API 返回 400
   - 去重：已存在则不重复添加
   - 添加后调用 `_save_blocked_keywords()` 持久化
   - 返回 `{"success": True, "keywords": [...]}`

3. **`remove_keyword(keyword)`**：
   - 存在则移除并持久化
   - 不存在仍返回成功（幂等）
   - 返回 `{"success": True, "keywords": [...]}`

4. **`toggle_keyword_filter(enabled)`**：
   - 设置 `_keyword_filter_enabled` 状态
   - 返回 `{"success": True, "enabled": bool}`

5. **API 路由**：
   - `GET /api/keywords` → `bridge.get_keywords()`
   - `POST /api/keywords` → `bridge.add_keyword()`，ValueError → 400
   - `DELETE /api/keywords/{keyword}` → `bridge.remove_keyword()`
   - `PUT /api/keywords/toggle` → `bridge.toggle_keyword_filter()`

## 技术决策记录

1. **关键词过滤层级**：过滤逻辑在 DanmakuBridge 的 `_on_danmaku_handler` 中执行（Task-07 实现），仅对 `message_type == "normal"` 生效。前端只负责显示，不参与过滤。Task-10 实现 CRUD API 和 UI 交互，过滤行为本身已在 Task-07 单元测试中覆盖。

2. **持久化复用已有方法**：`_load_blocked_keywords` 和 `_save_blocked_keywords` 在 Task-02 已实现。`add_keyword`/`remove_keyword` 调用 `_save_blocked_keywords()` 即可持久化到 `web/blocked_keywords.json`。

3. **幂等删除**：`remove_keyword` 删除不存在的关键词时返回成功而非 404。符合 RESTful 幂等语义——重复删除同一资源应得到相同结果。

4. **URL 编码处理**：DELETE 路由 `/api/keywords/{keyword}` 中的 keyword 是中文，aiohttp 会自动 URL 解码。前端使用 `encodeURIComponent(keyword)` 编码中文，aiohttp 的 match_info 自动还原。

5. **Playwright 验收策略调整**：验证标准10 原为"关闭过滤开关 → 所有弹幕正常显示"，但关键词过滤在后端执行，前端 `handleMessage` 不参与过滤。调整为验证开关 UI 交互和状态持久化，过滤逻辑本身由 Task-07 单元测试覆盖。
