### Task-07: 弹幕 WebSocket 推送 ⚠️

**实现文件**：
- `web/bridge.py`（`_on_danmaku_handler`、`_on_error_handler`、`_on_reconnect_handler`、`_on_status_change_handler`、`_setup_callbacks`）

**核心实现**：

1. **`_on_danmaku_handler(msg)`**：
   - 接收 DanmakuMessage 对象
   - 关键词过滤：仅对 `message_type == "normal"` 生效，gift/system 不受影响 → BR-005
   - 过滤禁用时所有消息都推送
   - 调用 `msg.to_dict()` 转换为前端格式，广播 `{"type": "danmaku", "data": {...}}`

2. **`_on_error_handler(error)`**：
   - 接收 Exception 对象
   - 广播 `{"type": "error", "data": {"message": str(error)}}`

3. **`_on_reconnect_handler(room_id)`**：
   - 接收 room_id 字符串
   - 广播 `{"type": "reconnect", "data": {"room_id": room_id, "status": "reconnecting"}}` → AC-012

4. **`_on_status_change_handler(room_id, status)`**：
   - 接收两个字符串参数
   - 更新 `_rooms` 中对应房间的状态
   - 广播 `{"type": "status_change", "data": {"room_id": room_id, "status": status}}`

5. **`_setup_callbacks()`**：
   - 调用 `listener.on_danmaku()`、`listener.on_error()`、`listener.on_reconnect()`、`listener.on_status_change()` 注册四个回调
   - 异常时仅 warning，不阻塞初始化

## 技术决策记录

1. **关键词过滤仅在 Bridge 层执行**：不过滤 gift/system 消息（BR-005），只对 `message_type == "normal"` 生效。过滤条件为 `any(kw in msg.content for kw in self._blocked_keywords)`，简单子串匹配。

2. **DanmakuMessage 序列化**：使用 `msg.to_dict()` → Pydantic 的 `model_dump()`，自动处理嵌套 `GiftInfo` 对象的序列化。

3. **`_setup_callbacks` 容错**：注册回调时如果 listener 尚未初始化（lazy-init 场景），catch 异常仅 warning。这在 `__init__` 中调用时 listener 还未创建，回调会在 `add_room` 中 listener 初始化后重新注册。

4. **`_on_status_change_handler` 的 room_key 匹配**：回调只接收 `room_id`，需要反向查找 `_rooms` 中对应的 `platform:room_id` 键。通过遍历 `_rooms` 的 key 以 `:{room_id}` 结尾来匹配。

5. **Task-08 代码已在 Task-06 预实现**：弹幕显示的 JS 和 CSS 代码在之前的任务中已经完整实现。本任务的重点是 Playwright 验收确认浏览器端行为正确。
