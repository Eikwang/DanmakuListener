# 合规与账号安全评审清单（阶段 0 前置，CEO 评审 F3 CRITICAL + Eng S-1）

> 本清单为**商业交付前置项**：未逐项完成并留存记录，不得进入试点部署。
> 本文件是模板与执行记录；每次新增平台或变更部署形态时重新过一遍。

## 1. 平台服务条款（ToS）风险评估

| 平台 | 逆向协议风险 | 账号封禁风险 | 风险等级 | 缓解 |
|---|---|---|---|---|
| B站 | 弹幕协议公开程度较高（社区生态成熟） | 低（游客可听） | 🟢 低 | 游客态优先 |
| 斗鱼 | 协议逆向常见 | 低-中 | 🟡 中 | 游客态优先 |
| 虎牙 | 协议含签名/加密 | 中 | 🟡 中 | 游客态优先 |
| 快手 | 需游客 token | 中 | 🟡 中 | 专用小号 |
| 抖音 | 代理抓包+伴侣 hook | 中-高（hook 触发检测） | 🟠 中高 | hook 单独知情确认 |
| 微信视频号 | 借用官方管理后台 | 中-高（多开风控） | 🟠 中高 | 独立小号+实测前置 |

## 2. 客户书面知情同意（模板要点）

- [ ] 明确告知：监听通过非官方技术手段实现，平台可能随时变更协议或加强风控
- [ ] 明确告知：使用客户的直播间/账号上下文，存在平台侧处置的理论风险
- [ ] 明确免责边界：因平台风控导致的监听中断，服务方按运维手册 SLA 响应但不承诺平台行为后果
- [ ] 客户签署日期与版本号（本文件同级归档）

## 3. 专用监听账号策略（硬约束）

- [ ] **严禁绑定客户主账号**——监听使用独立专用小号
- [ ] 每平台独立小号（封号爆炸半径隔离，Eng S-1）
- [ ] 游客态优先：能用游客 token 的平台（B站/斗鱼/虎牙）不用登录账号
- [ ] 小号池管理：账号来源、责任人、失效更换流程记录于 ops 手册

## 4. 抖音特有项（Eng R 项）

- [ ] **根 CA 安装**：安装范围告知（系统信任存储 vs 浏览器级）、可否限定代理域名、卸载步骤书面化
- [ ] **直播伴侣 hook 注入**：向第三方厂商进程注入代码，杀软误报率与 ToS 风险最高——需**单独知情确认**
- [ ] 运行期直播伴侣版本漂移检测（版本不符 → ROUTE_FAILED，fix_hint 指向版本锁定指南）

## 4.5 B站弹幕限流与登录 cookie（实测确认 2026-09-28）

- **实测结论**：游客（无 cookie）连接 auth 成功但 B站仅推送零星弹幕样本与统计事件——完整弹幕流需要登录态 cookie
- 获取方式：专用小号登录 B站 → 浏览器 F12 → Network 面板复制请求 Cookie 头（需含 SESSDATA、buvid3）
- 存放：`cookie/bilibili_cookies.txt`（一行 "SESSDATA=xxx; buvid3=xxx; ..." 格式）
- 合规：使用专用监听小号（不绑客户主账号），受 §3 硬约束覆盖

## 5. 数据合规

- [ ] 弹幕数据仅用于客户自有直播间的互动处理，不对外转售
- [ ] 用户昵称/ID 属于个人信息：AUTOlive 侧按其隐私政策处理，本系统不持久化（NOT in scope 一致）
